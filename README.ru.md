# turnrelay

[English](README.md) | [Русский](README.ru.md)

Туннелирование произвольного UDP-трафика через WebRTC TURN-релеи под видом
медиапотока звонка, с маршрутизацией через sing-box.

`turnrelay` - это Go-библиотека и CLI, которые открывают набор TURN-аллокаций
на релее (по умолчанию VK Calls, либо любой релей, к которому у вас есть
учётные данные), маскируют каждую под зашифрованный медиапоток WebRTC и
представляют их как единый UDP-канал. Поверх этого канала работает
WireGuard-туннель, а sing-box занимается собственно маршрутизацией, так что вы
получаете настоящие правила по доменам/geosite/geoip поверх транспорта,
который проходит в сетях, где доступны лишь несколько отечественных сервисов.

> **Статус: бета.** Библиотека, CLI `turnrelay-udp` и провайдер VK Calls
> работают целиком (что дальше - см. [ROADMAP](ROADMAP.ru.md)). Нативного
> outbound для sing-box пока нет; сейчас `turnrelay-udp` запускается рядом с
> sing-box.

> **Для исследовательских и учебных целей.** Прогон трафика через сервис
> звонков нарушает его условия использования и может привести к ограничению
> или блокировке аккаунта, создавшего ссылку на звонок. Используйте ссылки с
> одноразовых аккаунтов, держите число соединений умеренным и осознавайте
> риск, прежде чем на это полагаться.

## Зачем

Некоторые сети (мобильные операторы, корпоративный Wi-Fi, вайтлисты на уровне
страны) пропускают лишь горстку отечественных сервисов. Видеозвонки вроде
VK Calls обязаны там работать, поэтому их TURN-релеи находятся внутри белого
списка и их сложно заблокировать. Туннель через такие релеи, оформленный под
медиатрафик звонка, проходит вместе с ними.

Существующие инструменты для этого - отдельные VPN-приложения: они
маршрутизируют только по IP, не умеют правила по доменам/geosite, а на iOS
конфликтуют с лимитом «один VPN», если параллельно нужен маршрутизирующий
клиент. `turnrelay` сделан как транспорт, который потребляет полноценный
движок маршрутизации (sing-box), так что движок сохраняет свои правила и
нет схемы «VPN поверх VPN».

## Как это работает

```
ваш трафик ─▶ sing-box (правила маршрутизации)
                 └─ wireguard endpoint ──detour──▶ turnrelay
                                                      │  N TURN-аллокаций,
                                                      │  каждая под видом медиа
                                                      ▼
                          TURN-релей (в вайтлисте) ──▶ ваш VPS ──▶ интернет
```

- **turnrelay** открывает N параллельных TURN-аллокаций к релею по UDP. Их
  пропускная способность складывается. Каждая аллокация обёрнута слоем
  обфускации (по умолчанию DTLS-SRTP), так что классификатор релея видит
  медиапоток WebRTC.
- **WireGuard** (встроенный userspace-endpoint sing-box) работает поверх
  канала как L4-транспорт. Он используется *не* для маршрутизации и *не* как
  обфускация, а лишь чтобы мультиплексировать аллокации в один упорядоченный
  поток.
- **sing-box** применяет ваши правила и решает, что попадает в туннель.

Два сценария из одних и тех же кирпичей:

- **Выход за границей:** VPS вне ограниченной сети; turnrelay - точка выхода.
- **Detour:** VPS внутри ограниченной сети и пробрасывает трафик в другой
  туннель (VLESS, Hysteria2, ...), который уходит наружу, так что внешний
  туннель едет поверх turnrelay.

## Установка

Требуется Go 1.27+.

```bash
go install github.com/romanrublev/turnrelay/cmd/turnrelay-udp@latest
```

или из клона:

```bash
git clone https://github.com/romanrublev/turnrelay
cd turnrelay
make build        # соберёт bin/turnrelay-udp
```

## Быстрый старт

Нужен VPS (точка выхода) и, для провайдера VK, ссылка на звонок VK.

**1. Настройте сервер.** На свежем Debian/Ubuntu VPS от root:

```bash
scp scripts/vps-setup.sh root@<vps-ip>:/root/
ssh root@<vps-ip> './vps-setup.sh <vps-ip>'
```

Скрипт установит WireGuard и серверную часть, выведет ключи WireGuard и
адрес, на который направлять клиента. Полное описание, включая клиентский
конфиг WireGuard: [docs/server-setup.ru.md](docs/server-setup.ru.md).

**2. Запустите клиентский мост.** На своей машине:

```bash
turnrelay-udp \
  -provider vk \
  -link https://vk.ru/call/join/<hash> \
  -server <vps-ip>:56004 \
  -n 18
```

Дождитесь `worker 0 up`. Мост слушает `127.0.0.1:9000` и представляет канал
как обычный UDP-сокет, на который WireGuard-клиент указывает свой `Endpoint`.

**3. Маршрутизируйте через sing-box.** Дайте sing-box endpoint `wireguard`,
чей пир - `127.0.0.1:9000`, и пусть его правила решают маршрутизацию.
Минимальный конфиг и ключи - в [docs/server-setup.ru.md](docs/server-setup.ru.md).

## Настройка

Флаги `turnrelay-udp`:

| флаг | значение |
|---|---|
| `-provider` | `vk` (ссылка на звонок VK) или `static` (фиксированные учётные данные релея) |
| `-link` | ссылка на звонок VK; повторяйте для нескольких (провайдер `vk`) |
| `-turn`, `-turn-user`, `-turn-pass` | `host:port` релея и учётные данные (провайдер `static`) |
| `-server` | `host:port` вашего VPS с серверной частью |
| `-n` | число TURN-аллокаций (по умолчанию 30, около 18 на один credential) |
| `-mode` | обфускация: `srtp` (по умолчанию), `wrap`, `dtls` |
| `-tcp` | подключение к релею по TCP вместо UDP (медленнее, устойчивее) |
| `-listen` | локальный UDP-сокет (по умолчанию `127.0.0.1:9000`) |
| `-stats` | интервал логирования статистики |

Заметки:

- **UDP к релею - это дефолт и главный рычаг производительности.** TCP даёт
  деградацию «TCP поверх TCP»; переключайтесь на него только если UDP закрыт.
- **Соединения дают суммарную скорость, но они же - вектор бана.** Каждая
  аллокация выглядит как участник звонка. Держите `-n` умеренным; максимум 60.
- **Капча VK решается автоматически**, учётные данные кэшируются - обычно
  браузер не нужен.
